# 03 · MEMORY — the layer the design is still missing

This is the product. The pipeline is a byproduct. If the memory is right, an agent opens and already knows who it works for, what it is chasing, where it has been, and what worked — and never asks again.

---

## 1. The layers

Borrowed from Tencent's L0–L3 model, with one deliberate departure: **ours decays.**

| Layer | Files | Who owns it | How the agent gets it |
|---|---|---|---|
| **Identity** | `me.md` | **Human.** Agent may only propose. | In the cache, **in full**. It is two pages. |
| **Goals** | `goals/<id>.md` | Human sets, agent updates progress | In the cache, one line each |
| **Territory** | `territory/<id>.md` | Agent writes, human corrects | In the cache: **top 5 + stalest 3 + all blocked** |
| **Playbook** | `playbook/<id>.md` | Agent writes with evidence, human corrects | In the cache: **titles + one line**, body on request |
| **Learnings** | `learnings/<id>.md` | Agent proposes, human approves | In the cache: **active ones only**, compressed |
| **Records** | `data/**` | Agent writes through the pipeline | **Never in the cache.** Search only. |
| **Log** | `projects/*/log/` | Agent appends | **Never read by a working agent.** Only the Librarian. |

The asymmetry is the whole trick. Get it wrong and the context window is 90% stale contact records.

## 2. The hot cache — the single most important file in the app

`.scout/cache/context.md` — regenerated by `backend/memory.mjs` `renderCache()` whenever any memory file changes (debounced 2s). An agent's **entire wake-up read is this one file.**


### The budget is the feature

`MEMORY.CACHE_TOKEN_BUDGET = 2000` (≈8000 chars). **Enforced in code, gated by a test.** When the render exceeds it, `renderCache()` compresses in this fixed order and logs what it dropped:

1. Territory beyond top 5 / stalest 3 / all blocked
2. Playbook one-liners → titles only
3. Learnings older than 60 days that have not been re-verified
4. "Since your last run" → counts only
5. Goals → the behind ones only

An uncapped context file becomes exactly the overwhelm this app exists to prevent — for the agent as much as the human.

### Scoping

- `.scout/cache/context.md` — global
- `projects/<id>/.cache/context.md` — the project view: same shape, project brief in full, territory filtered to what this project touches
- An agent working a project reads the project cache **only**.

### Versioning

`v="184"` increments on every regeneration. An agent that cached a context can ask `GET /api/cache/version` — one cheap call — to know if it must re-read.

## 3. Territory — the object that stops the re-derivation

```yaml
---
id: nurses-ph
type: territory
kind: facebook-group          # facebook-group | hashtag | subreddit | account | site
label: Nurses PH
url: https://facebook.com/groups/...
access: joined                # untried | requested | joined | rejected | banned
access_changed: 2026-07-14
last_swept: 2026-08-17
sweep_interval_days: 7        # how often it's worth returning
finds: 34
wins: 4
rules: |
  No self-promo. Mods delete posts with links.
  Introductions welcome on Tuesdays.
posted:
  - { date: 2026-08-08, what: "intro post", url: "..." }
verified_at: 2026-08-17
---
```

`finds` / `wins` / `hit_rate` are **rollups over records whose `found_in` points here** — computed, never typed. `backend/territory.mjs` is their sole writer.

`access: rejected` plus `do not re-request` is as valuable as a win. It is a thing the agent would otherwise retry forever.

## 4. Decay — one function, every object

`backend/decay.mjs`:

```
staleness(obj) → 0..1
  age      = now - (verified_at || updated)
  window   = obj.sweep_interval_days ?? TYPE_WINDOW[obj.type]
  return clamp(age / window, 0, 1)
```

`TYPE_WINDOW`: territory 7d · playbook 30d · learning 90d · goal (its own deadline) · record 30d.

Consequences, all automatic:
- `staleness >= 1` → rendered stale: the freshness bar empties, the row drops toward `--fg-faint`.
- Playbook claims at `staleness >= 1` are **excluded from the cache** but stay in the file, and appear in the Librarian's weekly "re-verify or retire" list.
- Territory sorted by `staleness × hit_rate` gives "what should I sweep next" for free.

**This is the one place we deliberately depart from Tencent**, whose memory has no decay and only grows.

## 5. Learnings and graduation

```yaml
---
id: video-beats-photos
type: learning
claim: People who post video convert better than photo-only
scope: project                # project | global
project: 2026-08-hazing
evidence: [ "[[data/guests/maria-santos]]", ... ]   # 9 links
confidence: 0.72              # rollup: evidence count vs counter-examples
status: active                # proposed | active | retired
verified_at: 2026-08-15
---
```

- The agent **proposes**; the human approves on a card. Nothing enters memory silently.
- A `scope: project` learning that holds in a **second** project is proposed for **graduation to global** — that is the self-improvement loop, and it is the same promotion Tencent runs from L1 → L2 → L3, with the project as the scene.
- A learning whose evidence links break, or that is contradicted, drops confidence and eventually retires itself into the weekly report.

## 6. The Librarian

A scheduled agent, **sandboxed to `playbook/`, `territory/` and `learnings/`** — it cannot see `data/`, `me.md` or `goals/`. (Tencent chroots its consolidation agent for exactly this reason; it is why theirs doesn't corrupt everything.)

Weekly it:
1. Re-scores territory from real outcomes.
2. Re-verifies playbook claims against their evidence; retires the unsupported.
3. Proposes graduations and retirements.
4. Reports in **five lines**.

It may propose changes to `me.md` and `goals/`. It may never write them.

## 7. What the design is missing today — build these

1. **MEMORY screen** — `me` · goals · territory · playbook · learnings on one surface, each editable in place, each showing its age. It must be visibly obvious that editing here changes what the agent does tomorrow.
2. **GOALS** — a card per goal: the number, the progress, the days left, and which assistants are working it. Behind-schedule goals surface on TODAY.
3. **The cache, made visible** — a "what your agents know" panel that renders `context.md` read-only, with its token count and a **Regenerate** button. This is the single best trust-builder in the app: the person can see exactly what their assistant knows about them, and fix it.
