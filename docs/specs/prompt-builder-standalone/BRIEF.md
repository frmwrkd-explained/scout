# Standalone prompt builder — build brief

Status: **brief, not started.** Written 2026-08-14 for an agent building this in a **separate repo**.
FrameForge is the reference implementation and the eventual integration target; nothing here should
be built inside FrameForge yet.

**Read `catalog.json` next to this file first.** It is the entire prompt vocabulary — 12 angles,
20 camera moves, 245 style tokens across 11 axes, 7 look presets — each with its prompt fragment and
its thumbnail path. It is generated by `scripts/export-prompt-catalog.mjs`. **Do not retype any of
it and do not invent alternatives.** If something is missing from it, that is a bug in the export,
not licence to write your own.

---

## 1 — What this app is

A prompt builder for AI video models. **One job only.** No model picker, no generation, no
rendering, no cost estimates, no media library. The deliverable is a **prompt**.

It is **agent-first**. The user does not fill in a form. They say what they want — typed or spoken —
and an agent writes the shot list. The UI is where they *review and fine-tune* what the agent wrote.
That split is the whole design: **the agent writes, the human retimes and corrects.**

The output format is a segmented video prompt. This is the shape, taken from a real production pack:

```text
SCENE CONTEXT
Live-action photoreal feature-film shot, 8 seconds, a single continuous beat of a fight…

ACTIVE REFERENCES
@char_WD_bruiser_v1: heavy-set broad man, mid-thirties, 185cm… 100% matches the reference.

LOCATION MAP (exact positions)
BRUISER stands screen-left, three metres into the corridor…

GAZE AND EYELINES
BRUISER looks screen-right, locked on HOOD, and never breaks it…

FORMAT MODE
Controlled four-segment sequence with HARD CUTS. Real-time motion throughout. No dialogue.

SEGMENT 1 — HELD WIDE, GEOGRAPHY (0.0s–1.6s)
Both men already in position, breathing hard, water still running off both of them.
ACTION: BRUISER plants his back foot into the standing water and sets his weight over it.
LENS: locked low widescreen wide, deep focus down the corridor, soft oval bokeh.
SFX: <boots grinding into wet grit> <two sets of lungs working hard>

HARD CUT.

SEGMENT 2 — TIGHT COVERAGE, THE SWING (1.6s–3.4s)
…

PHYSICS
Real gravity, real inertia, real mass. Weight arrives before the limb that carries it…

LIGHTING
Four sodium vapour floods high on the container tops behind both men…

AUDIO
Diegetic only, no music. Rain runoff ticking off steel throughout…

STYLE
Fully photoreal live-action, 35mm filmic capture, widescreen 2.39:1 frame…

POSITIVE LOCKS
Four segments and exactly three hard cuts. The SAME two men appear in every segment…
```

### The grammar, measured across 14 real prompts

Block headers, by frequency: `PHYSICS` 17 · `POSITIVE LOCKS` 16 · `LIGHTING` 15 · `STYLE` 14 ·
`FORMAT MODE` 14 · `ACTIVE REFERENCES` 13 · `SCENE CONTEXT` 10 · `EVENT AND SHARED DIRECTION` 7 ·
`DIALOGUE` 7 · `AUDIO` 6 · `STAGING` 4 · `MICRO-BEHAVIOUR` 3 · `GAZE AND EYELINES` 3 ·
`LOCATION MAP` 2 · `STYLE LOCK` 3 · `CONTINUATION CONTEXT` 4.

Segment header is **invariant**: `SEGMENT N — LABEL (0.0s–1.6s)`. Ranges are **cumulative**, one
decimal, en dash `–` (U+2013), always starting at 0.0.

Per-segment sub-labels: `SFX:` 66 · `LENS:` 61 · `ACTION:`/`ACTION TASK:` 40 · `CAMERA:` 21 ·
`FACE:` 3.

Bracket grammar inside a segment: `{ }` dialogue · `< >` sound effects · `( )` music.

## 2 — The three hard rules

**① The app owns segments. Everything else rides through verbatim.**

Parse `SEGMENT N — LABEL (a–b)` headers and the sub-labels inside them. Every other block —
`PHYSICS`, `LOCATION MAP`, `POSITIVE LOCKS`, anything the agent invented — is stored as an
**opaque passthrough**: a `{ heading, body }` pair, listed by name, openable as plain text, and
otherwise never touched.

This is what keeps the UI small AND makes it lossless. You do not need a form for `PHYSICS`. You
need to know where the segments start and stop.

**Acceptance test: parse a prompt, re-emit it, diff must be empty.** Use the three fixtures in §9.

**② The catalogs are shortcuts into a text field, never a constraint on it.**

There are far more than 12 camera angles in the world. The 12 exist so the common case is one click.
Every picked value writes into an **editable line**, and a hand-typed line is exactly as valid.
Never block a value because it is not in the catalog. Mark hand-edited lines so the user can see
which are theirs.

**③ Once something is picked, its picker collapses.**

Do not leave a grid of 12 thumbnails on screen after one is chosen. Show the chosen thumbnail, its
name, `change`, `clear`. Same for moves, looks, everything. The default state is small; the expanded
state is opt-in and one click away.

## 3 — The UI

Two levels, and only two.

### Level 1 — the shot list (default)

A list you can read top to bottom. One line per shot:

```
 ①  [thumb]  0.0s   HELD WIDE, GEOGRAPHY · STATIC   Both men already in position, brea…   [1.6s|38f] ▢ ✕
 ②  [thumb]  1.6s   TIGHT COVERAGE, THE SWING · TRACKING   his weight arrives before h…   [1.8s|43f] ▢ ✕
 ③  [thumb]  3.4s   REVERSE, THE HIT LANDS · STATIC   The punch enters frame screen-le…   [2.0s|48f] ▣ ✕
 ④  [thumb]  5.4s   WIDE AGAIN, CONSEQUENCE · PULL OUT   HOOD goes back two heavy stum…   [2.6s|62f] ▢ ✕
```

Above it, a **proportional storyboard strip** — one block per shot, width ∝ duration, each wearing
its angle thumbnail. Drag the boundary between two blocks to trade time between them.

Below it, the passthrough blocks as a row of chips: `SCENE CONTEXT · ACTIVE REFERENCES · PHYSICS ·
LIGHTING · STYLE · POSITIVE LOCKS …`. Click one to read/edit it as text.

### Level 2 — one shot open

Click a row and only that row expands. Everything else stays a line.

```
LABEL     TIGHT COVERAGE, THE SWING
ACTION    [Tight on BRUISER's right hip and shoulder from behind and slightly below…]
ANGLE     [thumb] OVER-SHOULDER   change · clear          ← collapsed, because it is picked
CAMERA    Tracking In   change                            ← collapsed, because it is picked
LENS      over-the-shoulder shot, classic dialogue angle, camera travels with the subject…  ✎ EDITED
SAYS      [who] [the line]                        12/18w   ← only when SPEAKING is on
SOUND     soaked canvas snapping taut, boots grinding wet grit
FACE      [wants / blocked by / plays / turns on] ← only when ACTING is on
```

When nothing is picked, the angle row is 6 thumbnails + `all 12 →` + `✎ type it instead →`.

### The dial

**Keep this exactly as FrameForge has it.** Not `<input type="range">` — a drag-to-scrub control.
Grab the number, pull sideways: 1px = 1 frame, shift = quarter gear. It shows seconds **and** frames
(`1.8s` / `43f`) and a fill bar behind the number showing where it sits in range.

Time is **integer frames at 24fps** internally; seconds are display only. Sub-second beats are
common (flash cuts at 10 frames) and three 0.4s floats do not sum to the number on the total.

**Retiming is the product.** Change one duration and every downstream `(a–b)` rewrites, plus
`FORMAT MODE` if the counts moved. Lock a shot (`▣`) and a "fit to 8s" scales the others around it.
Doing this by hand in a markdown file is the pain this app removes.

## 4 — The agent

### The loop

1. User describes the shot. Text, or **voice** (Web Speech API is fine; whisper if you have it).
2. Agent writes the whole prompt — scene blocks + segments with timings.
3. It lands in the shot list. User reviews, retimes, corrects.
4. **Up to 3 follow-up requests per prompt.** "Make it 6 shots", "colder", "cut the dialogue".
   Show the count — `2 of 3 left` — and let a saved prompt be reopened for a fresh round later.

### Provider

**Gemini primary, with fallbacks.** Design the provider layer as an interface from hour one; do not
hardcode Gemini call shapes into the agent logic.

**Bring-your-own key is the headline, not a fallback.** Key entry is in onboarding, stored per user
profile, never logged, never sent anywhere but the provider. House keys exist for trials and must be
rate-limited and clearly labelled as shared. Say plainly whose key is being spent on every request.

### Pull, do not write

This is the most important instruction for the agent, and the reason `catalog.json` exists.

When the agent wants a look, a camera move, or a style, it **selects an id from the catalog** and the
app expands it into the full fragment. It does not write 80 words of cinematography that already
exist as `look_presets[3]`.

| Want | Agent emits | App expands to |
|---|---|---|
| A look | `{ look: "br2049" }` | the 10-axis pick set → assembled style fragment |
| A camera move | `{ move: "push-in" }` | `direction` per shot; `fragment` at clip level |
| An angle | `{ angle: "Over-shoulder" }` | the framing fragment + its thumbnail |
| A style axis | `{ filmstock: "CineStill 800T" }` | that token's fragment |

Same for the user's **own saved looks** and **community looks** — the agent gets the list with names
and ids, picks one, and the app expands it. A returning user's "the look from the dock film" should
cost the agent an id, not a paragraph.

Free text stays available for everything the catalog does not cover. See rule ②.

### What the agent must be told

- **Cumulative timecodes**, one decimal, en dash, starting at 0.0. Not durations.
- **2.5 words of dialogue per second, ceiling not target.** 12s buys ~26 words.
- **One camera action per segment.** Stacked moves produce jitter on every one of these models.
- **Past ~6 segments, identity drifts from the fourth cut.** Warn, do not block.
- **Photoreal work states constraints positively** (`POSITIVE LOCKS`), because naming an artefact
  summons it. **Stylised work needs its negations** (`NOT 3D, NO motion blur`) inside `STYLE LOCK`.
  Getting this backwards is the single most consequential mistake available here.
- **Never ask the video prompt to draw logos, emblems or on-screen text.** They corrupt. Leave clean
  negative space and composite in post.
- `MICRO-BEHAVIOUR` is boilerplate — the app appends it when acting is on. The agent never writes it.

## 5 — Looks and styles

Three sources, one picker:

1. **Presets** — the 7 in `catalog.json` (`br2049`, `noir`, `cyberpunk`, `goldenhour`, `verite`,
   `anderson`, `mythic`). Each is a pick set across the style axes.
2. **The user's saved looks** — created in this app, stored on their profile.
3. **Community looks** — shared, browsable, forkable.

A look is `{ id, name, fragment, picks{}, refImage?, fav }`. FrameForge's equivalents are
`GET /api/stylelocks` (record: `{ id, name, fav, created, updated, refImage, tags[], fragment }`) and
`GET /api/looks`. Match that shape and integration later is a copy, not a translation.

The user may pick a look **before** describing the shot, or let the agent choose, or ask the agent to
**create a new one** — which is then saveable to their profile like any other.

## 6 — Saving

Prompts save to the user profile: the parsed shot list **and** the passthrough blocks, so reopening
is lossless. Reopening restores a fresh 3-request budget. Version each save; a retime should not
destroy the previous timing.

## 7 — Thumbnails

`catalog.json` carries a `thumb` path for every angle and most style tokens
(`/axis-options/framing--over-shoulder.jpg`). **Hotlink them from the FrameForge host** rather than
shipping copies — 245 images is not worth duplicating, and they stay in sync for free. Set
`thumbnail_base` to the deployed host. Fall back to a neutral placeholder tile, never a broken image.

## 8 — Explicitly out of scope

Model selection · generation · rendering · cost estimation · media library · project management ·
anything that touches an image or video model. This app produces text.

## 11 — Coming back

The integration target is FrameForge's composer, which already mounts the shot list. Keeping these
aligned makes that a port rather than a rewrite:

- the shot record: `{ label, action, angle, move, lens, speaker, line, sfx, frames, locked }`
- frames at 24fps as the stored unit
- passthrough blocks as `{ heading, body }[]`, order preserved
- look records shaped like `/api/stylelocks`
- `catalog.json` consumed, never forked
